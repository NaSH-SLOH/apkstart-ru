# Руководство пользователя ApkStart и решения проблем

> Версия: v0.6.2 · Платформа: Windows 10/11 x64 · Обновлено: 2026-11-19
>
> ApkStart — среда выполнения Android-приложений для Windows: **Android-приложения устанавливаются как обычные программы Windows, появляются на рабочем столе и запускаются двойным кликом.**
> Сначала руководство объясняет, как пользоваться программой, а затем по «симптомам» даёт решения, которые можно выполнить шаг за шагом. Все шаги соответствуют реально существующим в программе кнопкам и меню.

## 1. ApkStart за 30 секунд

```
значок на рабочем столе (настоящий значок приложения .lnk)
      │ двойной клик
      ▼
ApkStart.exe --launch <имя пакета>
      │ среда выполнения Android не запущена? → запускается автоматически (эмулятор Android 14, встроен в пакет или скачивается при первом запуске)
      ▼
приложение открывается по точке входа, которую определила система (а не по жёстко заданной в APK главной Activity)
      ▼
окно эмулятора = окно приложения (смена заголовка, значка, портретных пропорций, центрирование в полноэкранном режиме)
```

**Возможности**

- 🖱️ **Установка двойным кликом по .apk**: после регистрации сопоставления файлов в Проводнике двойной клик по APK → автоматический разбор → установка → создание значка на рабочем столе.
- 🧩 **Один значок на рабочем столе для каждого приложения**: значок извлекается из APK локально, двойной клик по нему = сразу вход в приложение.
- 🪟 **Приложение — это окно**: нативный рендеринг, полноэкранный режим занимает всю высоту экрана с центрированием, в оконном режиме окно можно двигать и масштабировать, размер запоминается отдельно для каждого приложения.
- 🔍 **Находится поиском Windows**: два ярлыка — на рабочем столе и в меню «Пуск» (`程序\ApkStart\`).
- 📁 **Обмен данными**: `%USERPROFILE%\ApkStartShared` ↔ `/sdcard/ApkStartShared` внутри Android, двусторонняя синхронизация.
- 🪶 **Собственная среда выполнения**: не зависит от MuMu / LDPlayer / WSA и любых других эмуляторов, установленных на машине.

> Примечание: проект на ранней стадии, автор поддерживает его в свободное время, он открытый и бесплатный, без рекламы. Проблемы — это нормально, руководство как раз для этого.

## 2. Установка и первый запуск

### 2.1 Выбор подходящего варианта

Содержимое обоих источников одинаково, в Китае рекомендуется Gitee:

- GitHub: `github.com/RoutineMiku/apkstart/releases`
- Gitee: `gitee.com/daily-miku/apkstart/releases` (прямое подключение из Китая намного быстрее)

| Вариант | Имя файла | Когда выбирать |
|---|---|---|
| **Версия из Store** | `ApkStart_<версия из четырёх частей>_x64.msix` | Установка из Microsoft Store. Полная среда выполнения внутри, после установки сеть не нужна, обновления — через Store |
| **Полная портативная версия** | `ApkStart-v*-win64-full.zip` (около 830 MB, после распаковки ~1.3 GB) | Устанавливать не нужно, ждать загрузки тоже: распаковать и пользоваться, среда выполнения полностью в пакете |
| **Установочная версия** | `ApkStart-v*-Setup.exe` (около 1.3 GB) | Нужны ярлыки на рабочем столе и в меню «Пуск», а также запись для удаления |
| **Облегчённая портативная версия** | `ApkStart-v*-win64-portable.zip` (96 MiB, после распаковки ~227 MB) | Сначала просто попробовать, а среду выполнения скачать по сети при первом запуске |

> ⚠️ **Обязательно используйте последнюю версию (сейчас 0.6.2)**. В старых версиях (0.5.x и ранее) либо нет встроенной среды выполнения — и при каждом запуске идёт поиск или загрузка 1.5 GB, либо по умолчанию используется встроенное окно — это и есть типичный источник «очень медленно, не открывается, появляется окно с кнопкой поворота». При обновлении со старой версии убедитесь, что значок на рабочем столе указывает на каталог новой версии.

### 2.2 Что происходит при первом запуске

1. **(Только облегчённая версия) загрузка среды выполнения**: adb, Android Emulator, образ системы Android 14; на официальном источнике замерено 10+ MB/s, 8 потоков с разбиением на блоки + докачка с места обрыва. Полная и Store-версия этот шаг пропускают.
2. **Первое разворачивание образа**: образ xz распаковывается в `%APPDATA%\apkstart\system-images` (около 20 секунд, только один раз).
3. **Первое создание `/data`**: ApkStart сам создаёт пользовательские данные ext4 с шифрованием и метками SELinux (в официальном образе это лишь заполнитель на 1 MB).
4. **Автоматический запуск системы**: после этого запуск приложения сводится к одному `am start`, холодный запуск около 23 секунд, попадание в снимок около 10 секунд.

> Медленный первый запуск — это нормально, разовые затраты. Дальше вход занимает секунды.

## 3. Повседневное использование

### 3.1 Установка приложения

Любой из трёх способов:

- **Двойной клик по файлу APK** (сначала зарегистрировать сопоставление: Настройки → Интеграция с системой → связать файлы .apk);
- в главном окне выбрать «Установить приложение»;
- командная строка: `ApkStart.exe <путь\к.apk>`.

Поддерживаются раздельные пакеты `.apks` / `.xapk` (автоматически используется `install-multiple`). После установки автоматически создаются ярлыки на рабочем столе и в меню «Пуск».

### 3.2 Запуск приложения

Достаточно двойного клика по значку на рабочем столе. Все приложения используют одну среду выполнения, поэтому **второе приложение запускается почти мгновенно**.

### 3.3 Окно и отображение

| Действие | Способ |
|---|---|
| Переключение полноэкранного / оконного режима | `F11` или правый клик в меню трея. Полноэкранный режим только увеличивает окно и не меняет пропорции изображения |
| Смена ориентации (альбомная/портретная) | `Ctrl+Alt+R` (глобально) или кнопка поворота в заголовке окна; ориентация запоминается для этого приложения |
| Автоматический полный экран | Настройки → Отображение и окна → Автоматический полный экран (лучше всего работает вместе с принудительной ориентацией) |
| Принудительная альбомная/портретная ориентация | Настройки → Отображение и окна → Ориентация экрана |

> Среда выполнения перезапускается только в том случае, когда «ориентация панели не совпадает с ориентацией приложения» (около 40 секунд, в заголовке окна будет подсказка); приложения с той же ориентацией дальше открываются за секунды.

### 3.4 Горячие клавиши

| Клавиши | Действие |
|---|---|
| `F11` | Переключение полноэкранного / оконного режима |
| `Ctrl+Alt+R` | Поворот текущего приложения (альбомная/портретная) |
| `Ctrl+R` | Поворот внутри окна-оболочки (в режиме нативного окна используйте `Ctrl+Alt+R`) |

### 3.5 Обмен файлами (Windows ↔ Android)

Каталог `%USERPROFILE%\ApkStartShared` на этой машине и `/sdcard/ApkStartShared` внутри Android синхронизируются в обе стороны за секунды.
Вход: Настройки → Интеграция и файлы → Обмен файлами (можно «Синхронизировать сейчас» или «Открыть каталог»).

### 3.6 Навигация по странице настроек

Начиная с 0.6.0 параметры разделены на восемь категорий, сверху есть поле поиска (вводятся ключевые слова вроде «альбомная», «память», «прокси» — поиск идёт по всем категориям):

| Категория | Что внутри |
|---|---|
| Основное и установка | Среда выполнения и окружение, установка в один клик, автозапуск при старте, занятое место на диске и очистка |
| Отображение и окна | Режим отображения, автоматический полный экран, ориентация экрана, планшетная вёрстка, способ размещения окна |
| Управление и ввод | Назначение кнопок мыши, раскладка клавиатуры |
| Производительность и ресурсы | Политика ресурсов, качество графики, раздел данных, язык системы, снимки, прогрев при запуске |
| Сеть и загрузка | Источник обновлений и загрузки, ускоряющие зеркала, число потоков загрузки |
| Диагностика и исправление | Проверка системы, драйверы / патчи совместимости, автодиагностика |
| Интеграция и файлы | Рабочий стол и приложения, обмен файлами, интеграция с системой |
| Обновление и о программе | Обновление ПО, О программе |

### 3.7 Обновление по сети

Настройки → Обновление и о программе → Проверить обновления, либо правый клик в трее → Проверить обновления. При обновлении измеряется и выбирается самый быстрый источник (GitHub / Gitee / зеркало), загрузка идёт блоками параллельно, при ошибке источник меняется автоматически. Обновление не затрагивает среду выполнения, установленные приложения и снимки.

## 4. Три ключевых понятия (ключ к пониманию ошибок)

У большинства «странных проблем» причина — одна из трёх вещей ниже. Минута на понимание сильно упростит дальнейшую диагностику.

### 4.1 Среда выполнения / образ системы

ApkStart не эмулирует «пустой Android», а загружает в качестве основы **полный образ системы Android 14**.
В 0.6.2 есть только **один универсальный образ** (Google Play x86_64), на нём работают и x86-, и ARM-приложения — деления на «образ AOSP / образ совместимости», как в старых версиях, больше нет.

- Образ отсутствует / повреждён / несовместим со старыми пользовательскими данными → запуск системы не удаётся, загрузка зависает, идут повторные перезагрузки.
- Пользовательские данные (`/data`) — тонкий слой разницы, образ системы один на всю машину.

### 4.2 Аппаратное ускорение

Чтобы эмулятор работал быстро, нужно ускорение виртуализации CPU. В Windows есть только два пути:

| Способ | Что это | Кому нужны права администратора | Нужна ли перезагрузка после установки |
|---|---|---|---|
| **WHPX** | встроенная функция Windows «Платформа гипервизора Windows» (HypervisorPlatform) | при включении этой функции | нужна |
| **AEHD** | собственный драйвер ядра от Google | при установке драйвера | не нужна |

**Работает и без ускорения** (чистая программная эмуляция TCG), только запуск системы занимает минуты и картинка теряет кадры — это «медленно», а не «не удалось запустить». ApkStart автоматически откатывается и пробует до 4 наборов параметров в порядке «бэкенд рендеринга → способ ускорения → память / холодный запуск».

> Не путайте **VirtualMachinePlatform** (используется WSL2) с переключателем ускорения. Эмулятору нужна **HypervisorPlatform**. Если включена только первая, `emulator -accel-check` всё равно сообщит о недоступности.

### 4.3 Слой трансляции ARM

Подавляющее большинство китайских Android-приложений поставляются только с **нативными библиотеками ARM** (arm64-v8a / armeabi-v7a), а образ системы — **x86_64**; нужен «слой трансляции», который передаёт инструкции ARM процессору x86. В универсальный образ 0.6.2 встроен новый слой трансляции `ndk_translation`, поэтому для установки ARM-приложений обычно не требуется никаких настроек.

- При первой встрече с ARM-приложением, если компоненты слоя трансляции ещё не на месте, ApkStart сам доустановит образ совместимости, перезапустит среду выполнения и повторит попытку (см. 6.3).
- У старого образа (API 30) есть проблемы совместимости с новым слоем трансляции (например, приложения ByteDance вызывают `DoBadTrampoline` SIGABRT), в образе Android 14 это исправлено.

## 5. При проблеме сначала сделайте это: проверка системы и автодиагностика

Прежде чем листать это руководство, дайте программе самой всё проверить — большинство проблем она исправляет автоматически.

### 5.1 Проверка системы · автоматическая настройка

Где: Настройки → Диагностика и исправление → **Начать проверку**

- Что проверяется: включена ли виртуализация CPU (VT-x/SVM), доступны ли Hyper-V / платформа гипервизора, видеокарта / видеопамять / драйвер, память, версия системы, `emulator -accel-check`, драйвер AEHD.
- Кнопка «**Применить рекомендуемую конфигурацию**» автоматически записывает безопасные значения: память / число ядер / разрешение рендеринга / качество графики / принудительная программная эмуляция без ускорения, и сохраняет их как профиль этой машины, который потом применяется автоматически.
- Результаты ранжируются: `ok` (норма) / `warn` (работает, но стоит оптимизировать) / `bad` (без исправления не запустится). У каждого пункта есть цвет и пояснение.

Своими руками нужно сделать только два типа действий:
- **Виртуализация в BIOS**: перезагрузка и вход в BIOS → включить Intel VT-x / AMD SVM → Enabled (этот шаг программа выполнить не может).
- **Компоненты Windows / драйвер ускорения**: см. 6.1.

### 5.2 Автодиагностика (автоматический debug)

Где: Настройки → Диагностика и исправление → «Автодиагностика · умная диагностика»

В фоне каждые 10 минут проверяется вся машина, проблемы перечисляются по шести категориям, каждую можно **устранить в один клик** (перезапуск среды выполнения, снятие блокировки, удаление осиротевших процессов, аннулирование снимка, очистка диска, сброс сети Android…); после исправления проверка выполняется автоматически повторно:

| Категория | Какие проблемы охватывает |
|---|---|
| Среда выполнения | настоящая причина прошлой неудачной попытки запуска, зависание загрузки, остаточные файлы блокировки, осиротевшие процессы эмулятора, пустые оболочки снимков, отсутствие аппаратного ускорения |
| Подключение устройства | adb не авторизован, offline, среда выполнения работает, но adb не видит устройство |
| Хранилище | свободное место на диске, расхождение настроенного и фактического размера раздела данных, общая папка недоступна для записи |
| Настройки | конфликт ориентации экрана с физической панелью, автоматический полный экран не срабатывает в отдельном окне |
| Сеть / журнал | нет сети на стороне Android, источник загрузки недоступен, ошибки в свежем журнале |

> Два принципа: неудача проверки не считается проблемой (если состояние получить не удалось, сообщается «неизвестно», никаких выдуманных проблем); одно и то же старое напоминание не докучает повторно.

### 5.3 Экспорт отчёта диагностики

Где: Настройки → Диагностика и исправление → **Экспорт отчёта диагностики** (или одноимённая кнопка на странице интеграции с системой)

Отчёт — это обычный текст с конфигурацией машины, автоматически выбранными параметрами запуска, журналом и выводами диагностики. Приложите его при обращении — это сильно ускорит поиск причины.

### 5.4 Встроенное руководство и автоматические подсказки

Начиная с 0.6.2 это руководство **встроено в программу**: его можно открыть кнопкой «?» в заголовке главного окна или через «Открыть руководство» в разделе Настройки → О программе; доступны поиск, прокрутка, печать и сохранение в PDF. При открытии автоматически показывается раздел, связанный с текущей неисправностью.

Автодиагностика и автоисправление тоже подводят к подсказкам:

- когда автодиагностика находит проблему, справа от её пункта есть кнопка «Подсказка», открывающая нужный раздел;
- при проблемах с аппаратным ускорением, установкой, слоем трансляции ARM, авторизацией adb, отсутствием звука **после неудачи автоисправления автоматически открывается нужная подсказка** — листать руководство вручную не требуется;
- одна и та же подсказка за один сеанс открывается автоматически только один раз и не прерывает работу повторно.

> Открыть вручную: кнопка `?` в заголовке окна. Чтобы временно отключить автоматическое открытие, отключите уведомления в настройках автодиагностики; подсказки по-прежнему доступны по кнопке «Подсказка» в пункте проблемы.

## 6. Решения типичных проблем

### 6.1 Сообщение «аппаратное ускорение не включено» / система загружается долго

**Симптомы**: в настройках или диагностике сообщается «сейчас нет аппаратного ускорения», «аппаратное ускорение недоступно»; запуск системы занимает минуты, картинка теряет кадры.

**Сразу уточним**: обычно это «медленно», а не «не открывается». ApkStart уже автоматически откатился к программной эмуляции. Ускорение нужно только ради плавности.

**Действия зависят от версии:**

- **Установочная / портативная версия**: Настройки → Диагностика и исправление → Проверка системы → найти «аппаратное ускорение не включено» → нажать **Исправить**. Один раз появится UAC, WHPX включится автоматически; если включить не удалось (система не поддерживает или нажато «Нет»), автоматически установится драйвер AEHD.
- **Версия из Microsoft Store (MSIX)**: приложения из Store **не могут сами повысить права**, поэтому нажатие «Исправить» открывает диалог «Включение или отключение компонентов Windows»:
  1. отметить **«Платформа гипервизора Windows» (HypervisorPlatform)**;
  2. подтвердить и **перезагрузить компьютер** один раз.

  Либо выполнить в **PowerShell от имени администратора**:

  ```powershell
  dism /online /enable-feature /featurename:HypervisorPlatform /all /norestart
  dism /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
  ```

> Две ловушки: ① не включайте только VirtualMachinePlatform — это не то ускорение, которое нужно эмулятору; ② если в BIOS не включены VT-x/SVM, сначала включите их по 5.1, иначе компонент Windows ничего не даст.
> Драйвер видеокарты старше 3 лет стоит обновить с сайта производителя; но ApkStart не устанавливает драйверы автоматически (ошибка установки хуже). Некоторым старым видеокартам и встроенной графике нужен патч совместимости — см. Настройки → Диагностика и исправление → Драйверы · патчи совместимости.

### 6.2 Ошибка установки (INSTALL_FAILED_*)

**Симптомы**: при установке приложения возникает ошибка, текст обычно начинается с «Ошибка установки:» и заканчивается кодом `INSTALL_*`.

ApkStart переводит исходный английский текст ошибки на китайский. Действуйте по таблице:

| Код ошибки | Значение | Что делать |
|---|---|---|
| `INSTALL_FAILED_NO_MATCHING_ABIS` | приложение содержит только библиотеки ARM, а в текущем образе нет слоя трансляции ARM | **обычно обрабатывается автоматически**: ApkStart переключается на образ совместимости и повторяет попытку. Подробнее в [6.3](#63-в-образе-системы-нет-слоя-трансляции-arm--arm-приложения-не-устанавливаются-или-аварийно-завершаются) |
| `INSTALL_FAILED_OLDER_SDK` | приложению нужна более новая версия Android | нужен более новый образ системы; сейчас используется Android 14 (API 34), срабатывает крайне редко |
| `INSTALL_PARSE_FAILED_NO_CERTIFICATES` | у APK нет действительной подписи | APK повреждён или получен не из официального источника — заново получите установочный пакет |
| `INSTALL_PARSE_FAILED_INCONSISTENT_CERTIFICATES` / `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | подпись не совпадает с установленной версией | сначала удалить старую версию, затем установить |
| `INSTALL_FAILED_VERSION_DOWNGRADE` | на устройстве установлена более новая версия | понизить версию поверх нельзя: установить более новую или сначала удалить текущую |
| `INSTALL_FAILED_INSUFFICIENT_STORAGE` | недостаточно места на диске для среды выполнения | очистить диск или перенести каталог данных среды выполнения на диск с достаточным местом (Настройки → Интеграция с системой) |
| `INSTALL_FAILED_INVALID_APK` | APK повреждён / неполный | возможно, загрузка не завершилась — скачать заново |
| `INSTALL_FAILED_INVALID_URI` | путь к APK содержит спецсимволы или китайские иероглифы | переместить APK в путь только из латинских букв и установить снова |
| `INSTALL_FAILED_ALREADY_EXISTS` | уже существует пакет с тем же именем, но другой подписью | сначала удалить его |
| `INSTALL_FAILED_DEPRECATED_SDK_VERSION` | приложение рассчитано на очень старую версию Android | **обрабатывается автоматически**: ApkStart повторяет попытку с официальным обходным параметром |
| `INSTALL_FAILED_TEST_ONLY` | пакет только для тестирования | **обрабатывается автоматически**: добавляется параметр для тестовых пакетов и попытка повторяется |
| `INSTALL_FAILED_MISSING_SHARED_LIBRARY` | отсутствует нужная библиотека производителя / функция устройства | приложение требует специфического окружения производителя, которое эмулятор предоставить не может |
| `INSTALL_FAILED_USER_RESTRICTION` | система ограничивает установку | перезапустить среду выполнения и повторить |
| `INSTALL_FAILED_CONFLICTING_PROVIDER` | конфликт ContentProvider с уже установленным приложением | удалить конфликтующее приложение |
| `INSTALL_FAILED_INTERNAL_ERROR` | внутренняя ошибка системы (чаще всего нехватка места или незавершённый запуск) | перезапустить среду выполнения, дождаться завершения запуска и повторить |

> Если выводится исходный английский текст, которого нет в таблице, просто экспортируйте отчёт диагностики по 5.3 и пришлите его.

### 6.3 В образе системы нет слоя трансляции ARM / ARM-приложения не устанавливаются или аварийно завершаются

**Симптомы**: при установке выводится `INSTALL_FAILED_NO_MATCHING_ABIS` с текстом «приложение содержит только нативные библиотеки ARM… в текущем образе системы нет слоя трансляции ARM»; либо приложение устанавливается, но аварийно завершается сразу при запуске, а в журнале появляются `DoBadTrampoline`, `libndk_translation`, `UnsatisfiedLinkError`, `...so not found`.

**Принцип**: в 0.6.2 **один универсальный образ Android 14** поддерживает и x86, и ARM, слой трансляции встроен. В старых версиях образ приходилось переключать вручную; переключатель «Универсальный образ совместимости (управляется автоматически)» теперь **нужен только для совместимости со старыми конфигурациями, в обычной работе трогать его не нужно**.

**Что ApkStart делает автоматически:**

1. Если при установке появляется `NO_MATCHING_ABIS`, автоматически переключается образ совместимости → перезапускается среда выполнения → установленные приложения восстанавливаются из локальных резервных копий APK → установка повторяется (в журнале: «переключаюсь на образ совместимости и перезапускаю среду выполнения…»).
2. Если приложение падает при запуске и журнал явно указывает на слой трансляции ARM (например, `DoBadTrampoline`), автоматически выполняется переход на образ совместимости Android 14 и повторная попытка (в журнале: «обнаружен сбой слоя трансляции ARM, автоматически переключаюсь на образ совместимости…»).

**Что нужно сделать:**

- **Набраться терпения**: при переключении образа среда выполнения перезапускается, это занимает от 40 секунд до минуты, в это время может появляться окно с подсказкой.
- **Убедиться, что образ на месте**: Настройки → Основное и установка → Среда выполнения, посмотреть состояние «Универсальный образ совместимости (управляется автоматически)»; если показано, что не скачан, нажать «Скачать образ совместимости» (около 1.5 GB) и после завершения **перезапустить среду выполнения**.
- **Аварийное завершение остаётся**: у немногих приложений есть более глубокая защита от эмуляторов (принудительная проверка реальных датчиков, модема и т. п.), в эмуляторе они работать не будут; для таких приложений выводится пояснение — это ограничение, а не неисправность.

**Что делать, если отображается «красная „ошибка установки“», а текст при этом обещает „переключение на образ совместимости и повторную попытку“?**

Это ошибка отображения в старой версии: файл образа лежит на диске, но при использовании в старой среде выполнения без слоя трансляции переключение и повторная попытка пропускались, сразу выводилась ошибка, а текст подсказки по-прежнему сообщал «повторяю попытку». **Используется не самый свежий код — обновитесь до последней сборки 0.6.2** (в версии, которой соответствует это руководство, ошибка исправлена: перед установкой проверяется реальная способность текущей среды выполнения к трансляции, а не только наличие файла образа; `NO_MATCHING_ABIS` обязательно вызывает переключение, перезапуск и очистку старых снимков с последующей переустановкой; при повторной неудаче сообщается честно, без обещаний «повторяю попытку»). После обновления достаточно установить приложение ещё раз.

> Проверено на практике: Хунго дуаньцзюй (红果短剧, com.phoenix.read, только arm64-v8a) в образе Android 14 с новым слоем трансляции нормально устанавливается, открывает ленту рекомендаций и воспроизводит видео. У текущей среды выполнения `ro.product.cpu.abilist` = `x86_64,arm64-v8a`, слой трансляции работает.

### 6.4 adb не авторизован (разрешить отладку по USB)

**Симптомы**: в диагностике сообщается «adb не авторизован» или «авторизация отладки Android не завершена», `adb devices` показывает `unauthorized`, приложения не запускаются.

**Правильные действия (по порядку):**

1. Проверьте, не висит ли на экране окно эмулятора с диалогом **«Разрешить отладку по USB?»** — в этом окне нажмите **Разрешить** и отметьте **«Всегда разрешать отладку с этого компьютера»**, после этого вопрос больше не появится.
2. Если окно не нажимается или вообще не появляется: Настройки → Среда выполнения → **Сбросить данные Android / Очистить данные Android**, затем повторить (установленные приложения будут удалены, но файлы APK сохранятся и установятся заново автоматически; сама система не затрагивается).

> ⚠️ **Ни в коем случае не удаляйте `%USERPROFILE%\.android\adbkey`**. На практике это даёт обратный эффект: Android записывает новый открытый ключ только когда файла `adb_keys` не существует; после замены закрытого ключа старый открытый ключ в системе продолжает действовать, они не совпадают, и авторизация не проходит никогда.

> Проверка из командной строки: служба adb в ApkStart работает на **отдельном порту 5044** (полностью отделён от стандартного 5037):
> ```powershell
> $env:ANDROID_ADB_SERVER_PORT = 5044
> adb devices    # должен быть виден emulator-5554
> ```
> Не выполняйте `adb connect` вручную на порт 5555 — образ Play покажет «Разрешить отладку по USB?» поверх приложения, и это выглядит как поломка программы.

### 6.5 Двойной клик по значку не даёт результата / бесконечная загрузка / окно с кнопкой поворота

Такие проблемы почти всегда связаны с **точкой входа или перехватом окна**. Проверяйте по порядку.

**① Убедитесь, что используется новая версия программы**

- Посмотрите начало журнала `%APPDATA%\ApkStart\logs\app.log`: должно быть `start v0.6.2`. Если указано `v0.5.x`, значит значки на рабочем столе и в меню «Пуск» указывают на каталог старой версии.
- В старой версии (0.5.x) нет встроенной среды выполнения и по умолчанию используется встроенное окно → «очень медленно + окно-оболочка с кнопкой поворота». Перейдите на 0.6.2 и направьте ярлык на новый `ApkStart.exe`.

**② Заранее учтите время запуска**

Холодный запуск около 23–48 секунд, перезапуск при смене ориентации около 50 секунд — это норма. В это время кажется, что клик по значку «ничего не даёт», но система загружается в фоне. **Не кликайте несколько раз подряд**: второй экземпляр перехватит эмулятор, а завершение первого экземпляра может закрыть эмулятор вместе с собой, что приведёт к ошибке (в 0.6.2 добавлена защита `owner.pid`, но ожидание в очереди всё равно выглядит как отсутствие реакции). Нажмите один раз и дождитесь запуска.

**③ Нативное окно не перехвачено → откат к встроенному окну с кнопкой поворота**

Если в журнале есть `attach failed`, `emu:0`, значит агент окна не нашёл окно эмулятора и программа вернулась в режим встраивания (то самое окно-оболочка с заголовком и кнопкой поворота).
- Часто срабатывает при запуске через точку соединения каталога или из нестандартного пути; в 0.6.2 агент сначала разрешает реальный путь и только потом сопоставляет. Если проблема осталась, приложите журнал к обращению.

**④ Сброс данных Android (крайняя мера)**

Настройки → Основное и установка → **Сбросить данные Android** (есть повторное подтверждение). Установленные приложения и данные удаляются, но сама система сохраняется, список приложений остаётся, и при открытии они устанавливаются заново автоматически. Помогает при повреждении раздела данных и во всех случаях, когда `/data` не монтируется и приложение не открывается.

### 6.6 Краткая таблица прочих проблем запуска

Большинство этих ошибок среды выполнения ApkStart **обрабатывает автоматически**; в таблице указано, что именно делается и что можно сделать дополнительно. Если автообработка не помогла, экспортируйте отчёт диагностики по 5.3.

| Заголовок диагностики | Автоматическая обработка | Что можно сделать ещё |
|---|---|---|
| аппаратное ускорение недоступно | откат к программной эмуляции | включить ускорение по 6.1 |
| не удалось выделить память | уменьшение памяти и числа ядер | закрыть программы, занимающие память |
| порт эмулятора занят | автоматический выбор свободного порта | закрыть другие эмуляторы (Nox / MuMu / BlueStacks) или перезагрузиться |
| остаточный файл блокировки / «Running multiple emulators with the same AVD» | автоматическое снятие блокировки AVD и повтор | убедиться, что другой эмулятор не использует ту же среду выполнения |
| образ системы отсутствует / повреждён / несовместим со старыми данными | запуск системы с чистыми пользовательскими данными | Настройки → Среда выполнения: удалить образ и скачать заново |
| снимок быстрого запуска повреждён | старый снимок отбрасывается, выполняется холодный запуск | при следующем нормальном выходе он создастся заново; либо отключить снимки |
| компоненты среды выполнения удалены / нет библиотек VC++ | — | добавить ApkStart в исключения антивируса и распаковать заново; установить библиотеки Microsoft VC++ 2015-2022 |
| недостаточно места на диске | — | перенести каталог среды выполнения на диск с достаточным местом; отключить снимки / уменьшить раздел данных |
| путь содержит китайские символы / спецсимволы | автоматический переход на короткий путь | переместить ApkStart в каталог только из латинских букв (например, `C:\ApkStart`) |
| в CPU нет набора инструкций (AVX/SSE4) | — | чаще всего это предупреждение и система всё равно загружается; иначе нужна машина с поддержкой VT-x/AVX или старый движок |
| текущая среда выполнения не принимает этот режим GPU | выбор доступного режима GPU по версии движка | — |
| видеокарта / неизвестная ошибка | автоматические повторы с несколькими наборами параметров | обновить драйвер видеокарты; либо написать патч совместимости; если не помогло — экспортировать отчёт диагностики |

**Значок на рабочем столе показан как значок ApkStart / пустой значок**: Настройки → Интеграция с системой → **Пересоздать ярлыки** (ярлыки на рабочем столе и в меню «Пуск» перезаписываются по текущему списку приложений, вместе со значками и идентичностью в панели задач). Пересоздание нужно и в том случае, если ярлык был перемещён и путь перестал работать.

### 6.7 В приложении нет звука / звук очень тихий

**Симптомы**: в Android-приложении полностью нет звука видео и уведомлений; либо в других программах Windows звук есть, а в приложениях ApkStart нет.

**Сначала разберитесь**: если звука нет и в системе вообще, сначала займитесь звуком Windows; по шагам ниже идите, только если звук пропал именно в приложениях ApkStart.

1. **Громкость и устройство вывода Windows**: нажмите значок громкости на панели задач, убедитесь, что нет режима «без звука», громкость не 0, а устройством вывода выбраны используемые наушники или колонки. Откройте «Микшер громкости» и проверьте, не отключена ли отдельно строка ApkStart / среды выполнения Android и не выставлена ли там громкость 0.
2. **Громкость внутри приложения**: некоторые приложения при первом входе ставят громкость медиа на 0 — увеличьте её в настройках самого приложения или клавишами громкости на стороне Android. Bilibili / Douyin и подобные могут отдельно отключать звук автовоспроизведения внутри приложения.
3. **Переключатель звука ApkStart**: Настройки → Основное и установка → пункт **Звук Android-приложений** должен быть отмечен. Автодиагностика 0.6.2 проверяет этот пункт; если он отключён, об этом сообщается в «Настройки → Диагностика и исправление», и нажатие «Обработать» включает его в один клик. **После изменения обязательно перезапустите среду выполнения Android** (переключатель определяет, запускается ли эмулятор с `-no-audio`; изменение на ходу не даст звука сразу).
4. **Служба звука Windows**: нажмите `Win+R`, введите `services.msc`, найдите **Windows Audio** и убедитесь, что состояние «Выполняется», а тип запуска «Автоматически». Если служба отключена, запустите её через контекстное меню; это тоже обнаруживается и подсказывается автодиагностикой 0.6.2. В PowerShell от имени администратора можно выполнить `net start Audiosrv`.
5. **Bluetooth-наушники / несколько устройств вывода**: после переключения на Bluetooth-наушники Windows иногда не переносит туда уже запущенные программы. Отключите и снова подключите наушники либо перезапустите среду выполнения Android.
6. **Звука всё равно нет**: экспортируйте отчёт в «Настройки → Диагностика и исправление → Экспорт отчёта диагностики» и пришлите его; в отчёте есть состояние переключателя звука и службы аудио, что сразу показывает, в чём дело — в конфигурации, системной службе или самом приложении.

> При неудаче автоисправления программа сама открывает этот раздел. Если уведомления автодиагностики отключены, в раздел можно зайти вручную по кнопке «Подсказка» в пункте проблемы или по кнопке `?` в заголовке окна.

## 8. Данные и каталоги

| Назначение | Расположение |
|---|---|
| Среда выполнения (adb / emulator / образ) | встроена в пакет либо `%APPDATA%\apkstart\runtime` (облегчённая версия) |
| Развёрнутый образ системы | `%APPDATA%\apkstart\system-images` |
| AVD / установленные приложения / снимки | `%APPDATA%\apkstart\avd` |
| Значки приложений | `%APPDATA%\apkstart\icons\<имя пакета>.ico` |
| Настройки и список приложений | `%APPDATA%\ApkStart\settings.json` / `apps.json` |
| Журнал работы / отчёт диагностики | `%APPDATA%\ApkStart\logs\` |
| Общая папка Windows ↔ Android | `%USERPROFILE%\ApkStartShared` ↔ `/sdcard/ApkStartShared` |

> «Сброс данных Android» очищает только слой пользовательских данных, образ системы и файлы APK сохраняются; обновление программы не затрагивает среду выполнения, установленные приложения и снимки.
>
> Рекомендуется держать на диске C достаточно места: развёрнутый образ + раздел данных + снимки вместе занимают несколько GB. Нехватка места приводит к ошибкам установки и запуска системы.

## 9. Как получить помощь и оставить отзыв

При обращении приложите три вещи — это сильно ускорит поиск причины:

1. **Отчёт диагностики**: Настройки → Диагностика и исправление → экспорт отчёта диагностики;
2. **последние 20 строк app.log**: `%APPDATA%\ApkStart\logs\app.log`;
3. **версию и вариант сборки**: например, «версия из Store 0.6.2» или «полная портативная версия 0.6.2».
